# Перенос MegaLove

Репозиторий публичный. Никогда не добавляйте в него реальные анкеты, фотографии, базу, дампы, пароли, SSH-ключи, OAuth-токены, .env и реальные ссылки регистрации.

## Новый компьютер

Установите Git, Go 1.25+ и PostgreSQL 16 или Docker. Склонируйте репозиторий командой `git clone https://github.com/itmomegabattle/megalove.git`, затем `cd megalove`. Для тестов используйте отдельную пустую базу `megalove_demo`, задайте `DATABASE_URL`, `MEGALOVE_EVENT_SLUG=demo`, `MEGALOVE_VOTE_LOCAL_HTTP=1`, `MEGALOVE_ADMIN_LOCAL_HTTP=1`, запустите `go run . migrate`, `go run . demo`, затем `go run . serve`. Демоданные разрешены только в базе `megalove_demo`.

Чтобы включить локальную админку, сформируйте хеш безопасного тестового пароля командой `go run . admin-hash` и передайте его через переменную `MEGALOVE_ADMIN_HASH`. Адрес локального приложения http://127.0.0.1:8081/ . Тесты: `go test ./...`. Тесты PostgreSQL пропускаются без `MEGALOVE_TEST_DATABASE_URL`, который должен указывать на изолированную базу `megalove_demo`.

## Сервер и секреты

Рабочий сервер — Selectel, приложение `/opt/megalove/megalove`, unit `megalove`, Caddy и PostgreSQL работают рядом с другим приложением. Серверный `/etc/megalove.env` содержит конфигурацию и хеш админского пароля. Файлы Google-доступа указаны в нём, в том числе `/etc/megalove-vote-oauth.json` и `/etc/megalove-credentials/plan-b.json`. Не выводите их содержимое в чат или GitHub. Серверные секреты не нужны для простого клонирования.

На старом Windows-компьютере авторизованный SSH-ключ находится в `%USERPROFILE%\.ssh\codex_selectel_megabot_ed25519`, настройки подключения — в `%USERPROFILE%\.ssh\config` (профиль `selectel-megabot`), доверенный отпечаток сервера — в `known_hosts`. Скопируйте ключ по защищённому каналу вручную либо создайте новый ключ и добавьте его публичную часть на сервер. Секретный ключ нельзя публиковать. В `%LOCALAPPDATA%\MegaLove` хранятся OAuth-токены и зашифрованные копии. Эти копии DPAPI привязаны к старой учётной записи Windows, перенос файла сам по себе не обеспечивает расшифровку. Пароль админки не восстанавливается из его хеша.

## Безопасное обновление продакшена

Перед обновлением проверьте текущие состояния основного и тестового голосования и не перезапускайте сервис во время открытого приёма. Сохраните и проверьте резервную копию PostgreSQL вместе с фото, регистрационными ссылками, анкетами и голосами. Запускайте миграции и проверки на отдельной базе. Не меняйте настройки Caddy, PostgreSQL, другого приложения и сохранённые события без необходимости. Счётчики и содержимое базы до и после обновления нужно сверить.

Сборка из PowerShell:

```powershell
$env:GOOS='linux'
$env:GOARCH='amd64'
$env:CGO_ENABLED='0'
go test ./...
go build -trimpath -o deploy/megalove-linux-amd64 .
Get-FileHash deploy/megalove-linux-amd64 -Algorithm SHA256
```

Скопируйте бинарник и deploy/apply-admin-update.sh по SSH на сервер. Скрипт принимает путь к бинарнику и его SHA-256. Проверьте основное и тестовое голосование самостоятельно перед запуском: скрипт проверяет только основное. Пример при использовании профиля selectel-megabot:

```powershell
scp -O deploy/megalove-linux-amd64 deploy/apply-admin-update.sh selectel-megabot:/var/tmp/
ssh selectel-megabot 'bash /var/tmp/apply-admin-update.sh /var/tmp/megalove-linux-amd64 SHA256_ИЗ_GET_FILEHASH'
```

Подставьте настоящий SHA-256. Перезапуск сервиса выполняет миграции. Скрипт откатывает бинарник при ошибке проверки, но не отменяет миграции, поэтому резервная копия и проверка на отдельной базе обязательны. Затем проверьте `systemctl status megalove`, `curl -fsS http://127.0.0.1:8081/healthz`, статусы `/api/voting/status` и `/api/voting/test/status`, `journalctl -u megalove -n 50 --no-pager` и состояние соседнего приложения. Сверьте сохранность данных и текущей ссылки регистрации. Никогда не запускайте нагрузочный тест по действующему мероприятию, только на отдельной базе и отдельном экземпляре.
